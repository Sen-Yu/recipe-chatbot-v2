# 데일리 스크럼

데일리 스크럼은 하루에 한 파일 `YYYY-MM-DD.md`(그날 아침 날짜), 주간 스크럼은 한 주에 한 파일 `YYYY-Www.md`(ISO 주차, 월~일)로 씁니다. 업무 번호는 [업무 플로우](../workflow.md)와 같습니다.

## 보드에 기록하기

스크럼도 칸반 보드의 카드(이슈)로 남깁니다. 문서는 레포에 버전으로 남고, 보드에서는 날짜·주차별로 모아 봅니다.

| 기록 | 이슈 제목 | 라벨 | 보드 필드 | 열고 닫는 때 |
|---|---|---|---|---|
| 데일리 스크럼 | `[데일리 스크럼] YYYY-MM-DD (요일)` | `scrum:daily` | 종류=데일리 스크럼, 날짜, 주차 | 아침에 열고, 새벽 작업을 검토하면 닫습니다 |
| 주간 스크럼 | `[주간 스크럼] YYYY-Www` | `scrum:weekly` | 종류=주간 스크럼, 주차 | 월요일에 열고, 일요일에 닫습니다. 그 주의 데일리 스크럼을 하위 이슈로 묶습니다 |
| 업무 | `[업무 번호] 업무 이름` | — | 종류=업무, Status, 담당, 단계, 주차(이번 주에 다루는 것만) | 업무가 끝나면 닫습니다 |

이슈 본문은 스크럼 문서와 같은 내용입니다. 문서를 고치면 이슈 본문도 같이 고칩니다.

업무 상태는 [칸반 보드](https://github.com/users/Sen-Yu/projects/1)가 기준입니다. 스크럼은 그날의 요약과 트러블슈팅을 남기고, 업무는 이슈 번호(`#12`)로 가리킵니다.

## 네 가지 분류

| 분류 | 담는 것 | 누가 확인했나 |
|---|---|---|
| **어제 한 일 (Done)** | 어제 함께 진행해서 사용자가 확인한 일 | 확인함 |
| **오늘 할 일 (To Do)** | 오늘 할 일과 담당(사용자·Claude), 사용자가 정해야 하는 것 | — |
| **트러블슈팅** | 어제와 새벽에 막혔던 문제, 원인, 해결 방법, 남은 위험 | 해결한 것은 확인함 |
| **새벽에 한 일 (미검토)** | 사용자가 시키고 잔 뒤 Claude가 한 일 | **아직 확인 안 함** |

| 스크럼 분류 | 보드 칸 |
|---|---|
| 어제 한 일 | 완료 |
| 오늘 할 일 | 할 일, 진행 중, 결정 필요 |
| 새벽에 한 일 | 새벽 작업 · 검토 대기 |

- **새벽에 한 일**에는 결과마다 브랜치·커밋·PR을 적고, 사용자가 봐야 할 점("검토 포인트")을 함께 적습니다.
- 사용자가 검토를 마치면 그 항목은 다음 날 스크럼의 **어제 한 일**로 옮깁니다.
- 트러블슈팅은 "증상 → 원인 → 해결 → 남은 위험" 순서로 짧게 씁니다.

주간 스크럼도 같은 네 분류로 씁니다: **이번 주 한 일**(검토 끝난 일, 날짜별), **다음 주 할 일**, **트러블슈팅**(이번 주 주요 문제, 데일리 링크), **새벽에 한 일**(이번 주에 쌓인 미검토). 맨 위에 이번 주 목표, 맨 아래에 이번 주 숫자(커밋, PR, 테스트 등)를 둡니다.

## 틀

```markdown
# 데일리 스크럼 · YYYY-MM-DD (요일)

## 어제 한 일 (Done)
- (업무 번호) 한 일. 결과 링크

## 오늘 할 일 (To Do)
| 담당 | 업무 | 업무 번호 |
|---|---|---|

결정이 필요한 것:
| 항목 | 필요한 것 | 영향 |
|---|---|---|

## 트러블슈팅
| 문제 | 원인 | 해결 | 남은 위험 |
|---|---|---|---|

## 새벽에 한 일 (미검토)
| 작업 | 업무 번호 | 상태 | 결과 (브랜치·커밋·PR) | 검토 포인트 |
|---|---|---|---|---|
```
