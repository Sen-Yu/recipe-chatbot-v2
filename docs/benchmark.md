# 벤치마크 방법과 평가 지표

후보 모델을 역할별 평가 세트(`data/eval/`)로 돌려서 큰 모델 1개와 작은 모델 1개를 고릅니다. 로드맵 1.5(평가 지표)와 1.6(테스트 및 검증)에 해당합니다.

## 무엇을 돌리나

실행기는 그래프의 실제 노드 함수를 그대로 부릅니다. 같은 프롬프트, 같은 입력 메시지, 같은 구조화 출력 스키마를 씁니다. 그래서 점수가 곧 챗봇 안에서의 동작입니다.

| 역할 | 부르는 것 | 모델 | 채점 |
|---|---|---|---|
| supervisor | 수퍼바이저 메시지 (`_summary`) | 큰 모델 | 다음 행동이 정답 목록에 있는지. 정답에 조건이 있으면 조건(알레르기, 최대 칼로리, 최소 단백질)까지 맞는지 |
| ingredient | 재료 에이전트 노드 | 작은 모델 | 반영 후 보유 재료 집합이 정답과 같은지 (동의어 대표명 기준). 정답에 양이 있으면 양과 단위까지 |
| recipe | 레시피 에이전트 노드 | 큰 모델 | 형식(제목, 재료, 단계), 금지·알레르기 재료가 모든 후보에서 빠졌는지, 보유 재료 사용 수, 제목에 들어갈 말, 조리 시간 상한 |
| nutrition | 영양 에이전트 메시지 (`nutrition_message`) | 작은 모델 | 대체 재료 제안이 필요한 경우에만 제안했는지, 설명에 들어갈 말이 있는지 |
| selection | 입력 게이트 + 결정 노드 | 규칙 → 작은 모델 | 게이트 판단, 최종 처리(하나 확정, 되묻기, 수퍼바이저로)와 번호, 규칙만으로 정했는지 |

- **수퍼바이저**: 노드 함수가 아니라 같은 메시지로 모델을 직접 부릅니다. 노드는 순서 가드(레시피 없이 영양 계산 금지 등)로 결정을 고치기 때문에, 그 전의 모델 판단을 보기 위해서입니다.
- **요리 이름 요청**: 요청한 요리가 실제로 없는 경우(`dish_exists: false`)는 기대 동작이 아직 정해지지 않아서 채점하지 않습니다.

## 지표

| 지표 | 뜻 | 어떻게 세나 |
|---|---|---|
| 정답률 | 케이스의 모든 항목을 통과한 비율 | 통과 케이스 / 전체 케이스 |
| 구조화 성공 | 재시도까지 포함해 스키마에 맞는 출력을 냈는지 | 연결 오류를 뺀 케이스 중 `StructuredOutputError`가 없는 비율 |
| 첫 시도 성공 | 재시도 없이 바로 맞는 형식을 냈는지 | 모델을 부른 케이스 중 첫 호출이 유효한 비율 |
| 지연 p50 / p95 | 케이스 하나에 쓴 모델 호출 시간 (재시도 포함) | 모델을 부른 케이스의 호출 시간 합의 백분위수 (ms) |
| 연결 오류 | 엔드포인트 연결 실패, 시간 초과 같은 모델 밖의 실패 | 개수. 연속 5번이면 실행을 멈춥니다 |
| 항목별 통과율 | `next`, `constraints`, `must_not_contain` 같은 채점 항목 하나의 통과율 | 그 항목이 있는 케이스 중 통과 비율 |

**VRAM과 실행 환경**은 실행기가 재지 않습니다. 실행할 때 `--note`에 적어 둡니다. 예: `"RTX 4090 24GB, vLLM, AWQ 4bit, 최대 VRAM 14GB"`

## 모델을 고르는 기준

1. **안전 항목**: 레시피의 `must_not_contain`(알레르기·금지 재료)은 100%여야 합니다. 하나라도 틀리면 그 모델은 레시피 역할에서 뺍니다.
2. **구조화 성공 95% 이상**: 형식이 자주 깨지면 재시도 때문에 응답이 느려집니다.
3. **정답률**: 위 두 기준을 통과한 모델 중 역할별 정답률로 비교합니다.
4. **지연과 VRAM**: 정답률 차이가 5%p 안쪽이면 더 빠르고 가벼운 모델을 고릅니다.

큰 모델은 수퍼바이저와 레시피 점수로, 작은 모델은 재료·영양·선택 점수로 고릅니다. 기준선으로 v1이 쓰던 Gemini도 같은 세트로 돌릴 예정입니다(1.6). 이 실행은 OpenAI 호환 엔드포인트가 있어야 합니다.

## 실행

```bash
# 후보 하나를 모든 역할에 (Ollama 예시)
uv run python -m recipe_chatbot.benchmark run --base-url http://localhost:11434/v1 --model qwen2.5:7b \
    --name qwen2.5-7b --note "M2 Pro 32GB, Ollama Q4_K_M"

# 빠른 확인: 역할마다 3개만
uv run python -m recipe_chatbot.benchmark run --base-url http://localhost:11434/v1 --model qwen2.5:7b --limit 3 --name try

# 큰 모델과 작은 모델을 나눠서
uv run python -m recipe_chatbot.benchmark run --base-url http://localhost:8000/v1 --big-model BIG --small-model SMALL \
    --small-base-url http://localhost:11434/v1 --name big+small

# 결과 비교
uv run python -m recipe_chatbot.benchmark compare reports/benchmark/*/report.json --out reports/benchmark/compare.md
```

결과는 `reports/benchmark/<이름>/`에 두 파일로 남습니다.
- `report.md`: 역할별 표, 항목별 통과율, 틀린 케이스와 모델 출력
- `report.json`: 전체 기록

## 한계

- 평가 세트가 작습니다(v0 97개, 영양 4개). 1.1.2에서 300개로 늘린 뒤 다시 돌립니다.
- 레시피 품질(맛, 조리 순서가 자연스러운지)은 자동 채점하지 않습니다. 상위 후보 2~3개만 사람이 10개씩 읽어 봅니다.
- 레시피 검색(RAG)이 아직 연결되지 않아서, 레시피 역할은 검색 후보 없이 생성만 평가합니다. RAG 인덱스(L.5)를 붙이면 다시 돌립니다.
