# 레시피 RAG 검색

레시피 에이전트가 레시피를 만들 때 참고할 후보를 찾는 검색입니다(업무 플로우 L.5). 수집·정제한 레시피([레시피 수집](data-ingest.md)의 `rag.jsonl`)를 임베딩해서 인덱스로 저장하고, 보유 재료와 사용자 요청 문장으로 비슷한 레시피를 찾습니다.

## 구성

| 항목 | 선택 | 이유 |
|---|---|---|
| 임베딩 모델 | BAAI/bge-m3 (로컬, 1024차원) | v1과 같은 모델. 한국어 성능이 좋고 로컬에서 돌아갑니다 |
| 저장 | `vectors.npy` + `recipes.jsonl` + `meta.json` | 레시피 수천 개 규모라 별도 벡터 DB 없이 numpy 내적으로 충분합니다 |
| 임베딩할 글 | 요리 이름, 재료 이름, 조리 순서 앞 3단계 (300자) | 재료로 찾는 질의가 많아서 재료를 앞쪽에 둡니다 |
| 질의 | 사용자 요청 문장 + 보유 재료 | "된장찌개 레시피"처럼 재료 없이 요리 이름만 말해도 찾습니다 |
| 점수 | 코사인 유사도 + 보유 재료가 레시피에 하나 들어 있을 때마다 0.05 | 의미가 비슷해도, 가진 재료를 더 많이 쓰는 레시피를 앞에 둡니다 |

**다른 임베딩 모델로 만든 인덱스는 불러오지 않습니다.** 인덱스의 `meta.json`에 모델 이름을 적어 두고, 불러올 때 지금 모델과 다르면 멈춥니다. 벡터 공간이 섞이면 검색이 조용히 틀어지기 때문입니다(v1 원칙).

## 실행

```bash
uv sync --group rag   # sentence-transformers, torch (처음 한 번 bge-m3 약 2.3GB를 받습니다)

# 인덱스 만들기 (Apple M2 MPS 기준 레시피 2,812개에 약 2분 30초)
uv run python -m recipe_chatbot.rag build data/ingest/out/rag.jsonl --out data/rag

# 검색해 보기
uv run python -m recipe_chatbot.rag search data/rag 당면 시금치
```

- 그래프에서는 `rag.load_retriever()`로 검색기를 만들어 `Deps(retriever=...)`에 넣습니다.
- 인덱스 폴더는 `RECIPE_RAG_INDEX` 환경 변수로 정하고, 기본값은 `data/rag`입니다.
- 인덱스가 없으면 빈 검색기를 씁니다.
- 인덱스는 수집 원본에서 만든 파생물이라 커밋하지 않습니다(`.gitignore`).

## 확인한 것 (2026-11-25, 수집 레시피 2,812개)

- 인덱스 크기: 레시피 2,812개, 1024차원.
- 만드는 데 2분 30초가 걸렸습니다 (M2 MPS).
- 검색 한 번에 약 35ms가 걸립니다 (첫 검색은 약 200ms).
- 이름이 같은 레시피는 한 번만 보여 줍니다. 그래서 후보 3개가 '고등어조림 | 고등어조림 | 고등어조림'처럼 겹치지 않습니다.

| 보유 재료 | 요청 | 상위 3개 |
|---|---|---|
| 당면, 시금치 | | 잡채, 잡채요리, 빠른 잡채 |
| 김치, 돼지고기 | | 돼지고기 김치찌개, 김치찌개, 7분김치찌개 |
| 두부, 애호박, 된장 | | 된장국, 된장찌개, 냉이된장찌개 |
| 감자 | 반찬 | 감자조림, 부드런 감자조림, 감자전 |
| 닭고기 | 매콤한 거 | 닭갈비, 깐풍기, 닭강정 |
| 떡, 어묵 | | 떡볶이, 국물 떡볶이, 간장떡볶이 |
| 소고기, 무 | 국물 | 소고기된장찌개, 소고기 장조림, 무숙장아찌 ⚠ |
| 콩나물 | 해장 | 나물, 콩나물무침, 김치 콩나물 ⚠ |

약한 곳 (⚠):
- 소고기뭇국은 수집한 레시피에 없습니다. 수집 검색어에 없는 요리는 찾지 못합니다.
- 콩나물국은 27개나 있는데 위로 올라오지 않습니다. '해장' 같은 요청 말은 임베딩만으로는 약합니다. 레시피 에이전트가 후보를 받은 뒤 다시 고르는 단계에서 보완할 수 있습니다.
